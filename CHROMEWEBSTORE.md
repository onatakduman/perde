**Short Description** [REQUIRED]

Blurs text, images and video that mention or show the people you choose, on every site, before you see them.

(Turkish: Seçtiğin kişilerden bahseden ya da onları gösteren yazı, görsel ve videoları, her sitede, sen görmeden bulanıklaştırır.)

**Detailed Description** [REQUIRED]

```
Perde covers content about people you would rather not see. Add a name, and text, images and video that mention or show that person are blurred on every site before the page appears.

FEATURES
• Text — the name and its other spellings are matched regardless of capital letters and accents, and the whole card around the match is covered: the search result, the post, the video tile with its thumbnail.
• Images — pictures described by their caption, link or file name are covered at once. Pictures that only show the person are recognised by their face.
• Video — a playing video is covered while the person is on screen.
• Whole pages — a page whose title matches is covered entirely, with the choice to go back or show it anyway.
• Reference faces without looking — Perde finds public photos of the person on Wikipedia and learns the face from them, so you never have to search for pictures of someone you want to avoid. No photo is shown to you or kept.
• Three looks — blur, a grey block, or remove the content from the page.
• Reveal on click — one click uncovers a blurred block. Can be turned off.
• Per-site pause, a counter on the toolbar icon, and backup to a file.
• English and Turkish.

HOW TO USE
1. Click the Perde icon and type a name, or select a name on any page, right-click and choose "Perde: block".
2. Browse as usual. Covered content is blurred; the icon shows how many blocks are covered on the page.
3. Open "All settings" to add other spellings, manage reference faces, change the look, or pause a site.

WHAT TO EXPECT
Text and described images are covered before you can see them. A picture that needs a face check stays blurred until the check is done. Video is checked about twice a second, so the first moment of a scene can be visible. Face matching is not perfect: look-alikes can be covered and unusual photos can be missed, and you can make it stricter or looser. Protected (DRM) video cannot be checked.

PRIVACY
Perde has no account, no server and no analytics. Your block list, the reference faces and your settings stay on your device. Pages are read and images are compared inside your browser.
The only thing sent anywhere is a name you add, as a search to Wikipedia, Wikidata and Wikimedia Commons, to find other spellings and reference faces. You can turn this off in the settings.

PERMISSIONS
• "Read and change all your data on all websites" — a blocked name can appear on any site, so Perde has to look at every page you open to cover it. Nothing it reads leaves your browser.

SUPPORT
Perde is open source. Report a problem or suggest a change at: https://github.com/onatakduman/perde/issues

Version 0.2.0 — first public release.
```

## Permissions Justification

| Permission | Type | Justification |
|------------|------|---------------|
| `storage` | permissions | Saves the user's block list (names and other spellings), the reference face descriptors for those names, and the settings (look of covered content, sensitivity, paused sites). Stored locally with `chrome.storage.local`; nothing is synced or uploaded. |
| `contextMenus` | permissions | Adds one right-click item, "Perde: block “selected text”", shown only when text is selected, so a name can be put on the block list straight from a page. |
| `offscreen` | permissions | The face comparison model runs in one hidden extension page instead of in every tab. That page decodes images and compares the faces in them with the user's reference faces, entirely on the device. It is created the first time a page contains an image to check. |
| `<all_urls>` | host_permissions | The extension's single purpose is to cover content about blocked people wherever it appears, and a name or face can appear on any website, so the content script must run on every page. The same access is used to (1) download an image a second time from its original address so its faces can be compared on the device (pages usually load images from other domains, which a script cannot read without this), and (2) look a newly added name up on Wikipedia, Wikidata and Wikimedia Commons to find other spellings and public reference photos. Page content and images are never sent to the developer or any third party. |
| Content script on `<all_urls>` | content_scripts | Same reason as above: it reads the text and image descriptions of each page to find blocked names and blurs the matching blocks before they are painted. |

**Remote code:** none. All JavaScript is in the package. The face model library (`vendor/face-api/face-api.esm.js`) is the unmodified, minified build of the open-source @vladmandic/face-api package, version 1.7.15; `scripts/vendor-face-api.sh` in the repository reproduces it byte for byte. It is minified, not obfuscated.

## Review Notes

### Known Issues / Limitations

- **Broad host access.** `<all_urls>` is central to the single purpose and cannot be narrowed: both blocked names and the image servers pages load from are unpredictable. Expect the longer review that broad host permissions get.
- **Face recognition.** The extension compares faces in web images against reference faces the user set up, to hide those images from the user. It runs on the device, identifies no one to anyone else, and stores only numeric descriptors. If a reviewer asks, this is the relevant description.
- **Network requests on adding a name.** Disclosed in the popup, the settings page, the listing and the privacy policy; can be turned off.
- **Package size.** About 8 MB zipped, almost all of it the three face model files.
- **Not yet tested in branded Google Chrome.** The automated tests run in Chromium (Chrome for Testing). Load the unpacked extension in regular Chrome and try a few sites before submitting.
